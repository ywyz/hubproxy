## Run from source

With Git, Docker, and Docker Compose installed, run the following commands from the directory where you keep your source checkouts.

```bash
git clone --branch main https://github.com/ywyz/hubproxy.git
cd hubproxy
docker compose up -d --build
```

The included Compose file builds the `hubproxy:local` image, publishes the service on host port `5000`, and mounts `src/config.toml` read-only. The default configuration enables the web interface and common Linux package repositories.

## Verify the service

```bash
curl -fsS http://127.0.0.1:5000/ready
```

A ready service returns HTTP 200 and a JSON object containing `"ready":true` and `"service":"hubproxy"`. You can now open the [local web interface](http://127.0.0.1:5000/). To check an upstream request, fetch the headers for a file in the bundled Debian repository.

```bash
curl -fsSI http://127.0.0.1:5000/mirrors/deb.debian.org/debian/dists/stable/InRelease
```

Expect HTTP 200. If the request fails, run `docker compose logs --tail=50 hubproxy` from the checkout to inspect the service logs.

## Configure your deployment

- **Large downloads.** The default anonymous limit is 2 GiB per file. For larger downloads, set both `HUBPROXY_DOWNLOAD_USERNAME` and `HUBPROXY_DOWNLOAD_PASSWORD`, then run `docker compose up -d` to apply them. Browser users can sign in at `/login`. [Transfer capabilities](../../guides/capabilities/) · [Configuration reference](../../configuration/reference/)
- **HTTPS and mirror sources.** For public access, configure TLS with Caddy or Nginx. Edit `src/config.toml` to change which package repositories the proxy accepts. [Docker deployment](../../deployment/docker/) · [Reverse proxy](../../deployment/reverse-proxy/) · [Package mirrors](../../guides/package-mirrors/)
- **Upstream system packages.** By default, the install script downloads the `.deb`, `.rpm`, or `.apk` published by `sky22333/hubproxy`. Build from the checkout above to deploy the features documented for this fork. [System installation](../install/)
