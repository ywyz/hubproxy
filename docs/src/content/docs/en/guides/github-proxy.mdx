title: GitHub and Direct-Link Acceleration
description: Accelerate GitHub Release, Raw, Clone, API, Hugging Face, and arbitrary HTTPS direct-link downloads with HubProxy.
---

Requests that do not match `/v2`, `/token`, `/api`, or other registered routes are handled by the file proxy. Prefix the **full original URL** with your HubProxy host; if the URL matches a supported pattern, the handler reconstructs it and proxies to GitHub, Hugging Face, or another HTTPS upstream — otherwise it returns "invalid input".

## How to Accelerate

Prefix your original URL with the HubProxy host. Two formats are supported.

### Full URL (Recommended)

```bash
# Release download
curl -L -O "https://example.com/https://github.com/owner/repo/releases/download/v1.0.0/app.tar.gz"

# Git clone
git clone https://example.com/https://github.com/owner/repo.git

# API
curl "https://example.com/https://api.github.com/repos/owner/repo/releases/latest"

# Arbitrary HTTPS direct link
curl -L -O "https://example.com/https://ollama.com/download/OllamaSetup.exe"
```

:::note
Arbitrary HTTPS direct links are opt-in. Add each required host or path to `[access].directLinkWhiteList` first; a missing or empty list makes every arbitrary direct link return 403. GitHub, Hugging Face, and Docker repositories continue to use the existing `whiteList` / `blackList`.
:::

### Global Git acceleration

Use `url.<base>.insteadOf` so every `https://github.com/` clone/fetch goes through HubProxy automatically:

```bash
git config --global url."https://example.com/https://github.com/".insteadOf "https://github.com/"
```

Then clone as usual:

```bash
git clone https://github.com/owner/repo.git
# actually requests https://example.com/https://github.com/owner/repo.git
```

To remove:

```bash
git config --global --unset url.https://example.com/https://github.com/.insteadOf
```

### Omit `https://`

HubProxy auto-prepends the scheme:

```bash
curl -L -O "https://example.com/github.com/owner/repo/releases/download/v1.0.0/app.tar.gz"
```

:::caution
**Not supported:** path-prefix rewrites like `https://example.com/gh/owner/repo/...` or `/raw/owner/...` — these return "invalid input".
:::

## Supported URL Types

| Type | Path pattern |
|------|-------------|
| Release / Archive | `github.com/{owner}/{repo}/releases/...`, `/archive/...` |
| Raw / Blob | `github.com/{owner}/{repo}/raw/...` (`/blob/` auto-converted to `/raw/`) |
| Git protocol | `github.com/{owner}/{repo}/info/...`, `/git-...` |
| Raw domains | `raw.githubusercontent.com/...`, `raw.github.com/...` |
| API | `api.github.com/repos/{owner}/{repo}/...` |
| Gist | `gist.github.com/...`, `gist.githubusercontent.com/...` |
| Hugging Face | `huggingface.co/...`, `cdn-lfs.hf.co/...` |
| GitHub Assets | `github.githubassets.com/...`, `opengraph.githubassets.com/...` |
| Arbitrary HTTPS direct link | `https://ollama.com/download/OllamaSetup.exe`; a file path is required |

## Script Nesting

HubProxy can rewrite GitHub URLs inside `.sh` / `.ps1` install scripts (max 10MB). Behind a reverse proxy, set `X-Forwarded-Host` correctly — see [Reverse Proxy](/en/deployment/reverse-proxy/).

## Limits and Blocks

| Limit | Description |
|-------|-------------|
| Web content | `text/html`, `application/xml`, etc. are blocked (403) — not for browsing GitHub pages |
| Direct-link methods | Only `GET` and `HEAD` are allowed; Git smart HTTP and existing GitHub/Hugging Face methods are unchanged |
| Direct-link request headers | Only download headers such as a single byte `Range`, validators, `Accept`, and `User-Agent` are forwarded; multi-range requests return 416, and `Authorization`, `Proxy-Authorization`, `Cookie`, and arbitrary custom headers are never forwarded |
| Direct-link response headers | Responses are forced to `application/octet-stream` with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`; origin authentication state such as `Set-Cookie`, `WWW-Authenticate`, and `Proxy-Authenticate` is removed |
| Redirects | The HTTP client does not auto-follow. Relative `Location` values are resolved against the current URL, and every direct-link hop is rechecked for HTTPS, access-list permission, and a public target address. Rewritten bodyless redirects drop entity headers, and external redirects follow standard method semantics; a `307`/`308` that would require replaying a consumed body returns 502 |
| File size | `[server].fileSize` caps single-file downloads (default 2GB). A direct-link GET is staged in a system temporary file while reading at most the limit plus one byte, so an oversized response returns 413 before any upstream body is sent. A process-wide quota keeps aggregate staged content within that “limit plus one byte,” with at most 16 requests staging concurrently; a full quota or concurrency limit fails fast with 503. Upstream retrieval and staging are canceled with 504 if the response body makes no progress for two minutes or the direct-link operation (including all redirects) exceeds 30 minutes. A `206` response is also checked against the complete size in `Content-Range`; GitHub/Hugging Face keep their existing streaming and Range behavior |
| Resource access | `[access].whiteList` / `blackList` restrict repositories and images only; `directLinkWhiteList` / `directLinkBlackList` independently restrict arbitrary direct links. A missing or empty direct-link allowlist denies by default. Direct links reject traversal, encoded delimiters, and recursively encoded percent signs before matching `{host}/{path-and-query}`. Hosts are case-insensitive and numerically equivalent ports are canonicalized, so omitted HTTPS ports, `:443`, and `:0443` are equivalent; paths and queries remain case-sensitive and are not whitespace-trimmed |

HubProxy resolves direct-link hosts locally, requires every candidate address to be public, and tries the validated addresses in order. Proxy and `NO_PROXY` selection is evaluated against the original hostname before the connection is pinned to a validated IP. Hosts that are resolvable only by a SOCKS5 proxy are intentionally rejected because the proxy protocol does not reveal the actual destination IP for this SSRF check. Client disconnects cancel the upstream request and temporary-file staging. The pinned transport created for each request closes idle connections when the response ends. Access-denial logs omit direct-link query strings so signed URL credentials are not recorded.

:::danger
Do not set `directLinkWhiteList = ["*/*"]` on a public instance unless you intentionally operate an open download proxy. Allow only the hosts or paths you need, and allow each CDN redirect host as well. The legacy `whiteList = ["*/*"]` does not enable arbitrary direct links.
:::

Large Release files support `wget -c` resume — see [Transfer Capabilities](/en/guides/capabilities/).

```toml
[server]
fileSize = 2147483648

[access]
whiteList = ["trusted-org/*"]
blackList = ["*/malicious-repo"]
directLinkWhiteList = ["ollama.com/download/*"]
directLinkBlackList = []
```
