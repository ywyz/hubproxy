description: 使用 HubProxy 加速 GitHub Release、Raw、Clone、API、Hugging Face 与任意 HTTPS 直链下载。
---

未匹配 `/v2`、`/token`、`/api` 等路由的请求，由文件代理处理器接管。使用时在**完整原始 URL** 前加上 HubProxy 域名；匹配支持的 URL 类型后，处理器还原地址并代理到 GitHub、Hugging Face 或其他 HTTPS 上游，不匹配则返回「无效输入」。

## 加速方式

在原始 URL 前加上 HubProxy 域名，支持两种写法。

### 完整 URL（推荐）

```bash
# Release 下载
curl -L -O "https://example.com/https://github.com/owner/repo/releases/download/v1.0.0/app.tar.gz"

# Git Clone
git clone https://example.com/https://github.com/owner/repo.git

# API
curl "https://example.com/https://api.github.com/repos/owner/repo/releases/latest"

# 任意 HTTPS 直链
curl -L -O "https://example.com/https://ollama.com/download/OllamaSetup.exe"
```

### Git 全局加速

配置 `url.<base>.insteadOf` 后，所有 `https://github.com/` 开头的 clone/fetch 会自动走 HubProxy，无需每次手动改 URL：

```bash
git config --global url."https://example.com/https://github.com/".insteadOf "https://github.com/"
```

之后可直接：

```bash
git clone https://github.com/owner/repo.git
# 实际请求 https://example.com/https://github.com/owner/repo.git
```

取消配置：

```bash
git config --global --unset url.https://example.com/https://github.com/.insteadOf
```

### 省略 `https://`

HubProxy 会自动补全协议头：

```bash
curl -L -O "https://example.com/github.com/owner/repo/releases/download/v1.0.0/app.tar.gz"
```

:::caution
**不支持**将域名替换为路径前缀的写法，例如 `https://example.com/gh/owner/repo/...` 或 `/raw/owner/...` 会返回「无效输入」。
:::

## 支持的 URL 类型

| 类型 | 匹配路径示例 |
|------|-------------|
| Release / Archive | `github.com/{owner}/{repo}/releases/...`、`/archive/...` |
| Raw / Blob | `github.com/{owner}/{repo}/raw/...`（`/blob/` 自动转为 `/raw/`） |
| Git 协议 | `github.com/{owner}/{repo}/info/...`、`/git-...` |
| Raw 域名 | `raw.githubusercontent.com/...`、`raw.github.com/...` |
| API | `api.github.com/repos/{owner}/{repo}/...` |
| Gist | `gist.github.com/...`、`gist.githubusercontent.com/...` |
| Hugging Face | `huggingface.co/...`、`cdn-lfs.hf.co/...` |
| GitHub Assets | `github.githubassets.com/...`、`opengraph.githubassets.com/...` |
| 任意 HTTPS 直链 | `https://ollama.com/download/OllamaSetup.exe`；必须包含文件路径 |

## 脚本嵌套加速

HubProxy 可自动改写 `.sh` / `.ps1` 安装脚本中的 GitHub URL（脚本最大 10MB）。反代部署时需正确设置 `X-Forwarded-Host`，详见 [反向代理配置](/deployment/reverse-proxy/)。

## 限制与拒绝

| 限制 | 说明 |
|------|------|
| 网页内容 | `text/html`、`application/xml` 等网页类型会被拒绝（403），不能用来加速 GitHub 网页浏览 |
| 通用直链方法 | 只允许 `GET`、`HEAD`；Git smart HTTP 与 GitHub/Hugging Face 仍保留原有方法 |
| 通用直链请求头 | 只转发下载所需的允许列表头（如单区间 `Range`、条件请求头、`Accept`、`User-Agent`）；多区间请求返回 416，且不会转发 `Authorization`、`Proxy-Authorization`、`Cookie` 或任意自定义头 |
| 通用直链响应头 | 强制使用 `application/octet-stream`、`Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`；同时移除 `Set-Cookie`、`WWW-Authenticate`、`Proxy-Authenticate` 等来源站认证状态头 |
| 重定向 | HTTP 客户端不自动跟随；相对 `Location` 会基于当前 URL 解析，每个直链跳转均重新检查 HTTPS、访问列表以及公网目标地址。无正文的重写重定向会移除实体头；外部重定向遵守标准方法语义，需要重放已消费请求体的 `307`/`308` 返回 502 |
| 文件大小 | `[server].fileSize` 控制单文件上限，默认 2GB。通用直链 GET 会先写入系统临时文件并最多读取上限加 1 字节；超限时在输出响应体前返回 413。暂存过程串行执行，使临时磁盘总占用不超过一个已配置的单文件上限。`206` 响应还会校验 `Content-Range` 中的完整文件大小；GitHub/Hugging Face 保持原有流式与 Range 行为 |
| 资源访问 | `[access].whiteList` / `blackList` 限制可代理的仓库或直链；直链先拒绝目录遍历和编码分隔符，再按 `{域名}/{路径和查询}` 匹配。域名不区分大小写，缺省 HTTPS 端口与 `:443` 等价；路径与查询保持大小写敏感且不做空白裁剪 |

通用直链解析域名后会验证全部候选地址均为公网地址，并按候选地址依次尝试连接；客户端断开时，上游请求和临时文件暂存会随请求上下文停止。每次请求使用的固定目标传输会在响应结束后关闭空闲连接。访问拒绝日志不记录直链查询字符串，避免把签名 URL 凭据写入日志。

:::danger
启用任意直链后，未配置 `[access].whiteList` 的公网实例可能被当作开放下载代理滥用。强烈建议只允许所需域名或路径；若下载会跳转到 CDN，还需将跳转后的域名加入白名单。
:::

Release 等大文件支持 `wget -c` 断点续传，见 [传输特性](/guides/capabilities/)。

```toml
[server]
fileSize = 2147483648

[access]
whiteList = ["trusted-org/*", "ollama.com/download/*"]
blackList = ["*/malicious-repo"]
```
